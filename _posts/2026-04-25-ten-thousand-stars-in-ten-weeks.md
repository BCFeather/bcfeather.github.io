---
title: "Ten thousand stars in ten weeks"
date: 2026-04-25 21:00:00 +0800
categories: [technology]
description: "A TypeScript repository with no description crosses ten thousand GitHub stars seventy days after it was created."
---
A repository called t3code appeared on GitHub on 14 February with no stars, no description and a TypeScript codebase. By 25 April it had ten thousand stars, and the curve that produced them kept its slope. By the first week of November the count stood above forty-six thousand, with more than nine thousand forks and a single week that added over sixteen thousand stars. Very few projects move that fast, and almost none of them do it while saying nothing about what they are.

The account behind it belongs to a developer who is well known for streaming and for opinionated software takes, and an audience that size can move a star count in a way that a good README cannot. Stars are bookmarks rather than reviews, and a mention to several hundred thousand followers converts at a rate that ordinary open-source projects never see. That explains the first thousand. It does not explain the forks, and it does not explain a growth rate that accelerated in the autumn rather than decaying. The conversion rate is worth measuring, because it sets the ceiling for every project that launches without a front page.

Forks are the more interesting number, because a fork is a decision to keep a copy rather than a gesture of approval. Nine thousand forks against forty-six thousand stars is a high ratio by the standards of link-and-forget repositories, and it suggests people intend to run the thing. For a code project the practical test is whether it survives contact with a real machine, and the fork count is the cheapest proxy available for how many people tried.

The absence of a description is itself a signal about how open source now spreads. A repository used to need a front page that explained installation, scope and licence, because discovery happened through search. Discovery now happens through a person, a clip and a link, and the explanation arrives in a video rather than in a file. Projects that grow this way tend to acquire documentation later, written by people who have already worked out the rough edges. Documentation arrives when somebody needs it, and the timing is decided by the audience rather than by the author.

Velocity of this kind also carries risk, and the pattern has repeated often enough to be predictable. A repository with no stated scope attracts feature requests it never promised, forks that diverge, and issues filed against expectations that were never written down. The maintainer has one account, one attention budget and a public that expects daily progress. Projects that survive the spike are the ones where a licence, a scope statement and a contribution rule appear within the first months, quietly, while attention is still high.

What t3code will be is still unknown, and that is the honest state of the record. What can be measured is a curve that started at zero in mid-February and had passed ten thousand in ten weeks, and a fork count that suggests the downloads were real. A star is a bookmark, so the count tells you what developers noticed rather than what they use. The notices are the only thing that arrives early, which is why they are worth watching.
